Start with `AGENTS.md` — it is the working guide: the non-negotiable brand and accessibility rules, the repo map, how to build a page / artwork / component, and the checks to run before handing anything over. For any question about what the brand itself actually specifies — palette values, CMYK, the selo's versions and clearspace, the motif, voice, or the Sab.IA platform — go to `docs/brand-manual.md`, which extracts the official manual and marks where this system deliberately departs from it. For decks, pitches, reports, posters, social cards and one-pagers, in any stack (HTML, PPTX, SVG, a print pipeline), start at [`DESIGN.md`](DESIGN.md): it routes by intent to the composition rules, the formats, the exemplars and a self-check rubric, and needs no install step. Then `readme.md` (brand, voice, visual foundations, caveats), `docs/` (generated component and token references, recipes, quality checklist), `tokens/` (colours, type, spacing, layout, themes), `components/*/*.prompt.md` (per-component usage rules), `docs/guidelines.md` (imagery, motion, theming, accessibility), `showcase/index.html` (the whole system, live), and `starters/` + `templates/` (deck, program page, printable enrollment form, landing page, blank page, A3 poster) for ready-made starting points.
If creating visual artifacts (slides, mocks, throwaway prototypes, etc), copy assets out and create static HTML files for the user to view. **Be creative and ambitious inside the brand invariants**: pick a concept, give the piece an awe moment, use diagrams, subtle gradients, choreographed motion, interaction and (where it serves the idea) Three.js or other 3D, with clear structure and great UX. Read `docs/composition/creative-latitude.md` and `docs/composition/artifact-craft.md` first; do not fall back on the same layout each time. If working on production code, you can copy assets and read the rules here to become an expert in designing with this brand.
To put this system into a project that is not this repo — a website, a React app, a CMS theme, a Python or print generator — read `docs/integration.md` (the npm package on GitHub Packages, or the versioned static kit) and `RULES.md`. For any consumer that is not a browser, `brand.json` is the brand contract (palette with CMYK, rules, assets by role) and `dist/tokens.json` holds every token resolved per theme. Tokens are named `--rse-*`; the source is `tokens/src/*.tokens.json` (DTCG).
If the user invokes this skill without any other guidance, ask them what they want to build or design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production code, depending on the need.
