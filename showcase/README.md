# showcase/ — the system, in one document

`index.html` is the design system's single documentation site: one page that presents the whole
system to a non-technical audience (leadership, partners, new team members) and is, at the same
time, the working reference for the people who build with it. It replaced the 38 specimen cards
that used to live in `guidelines/` and next to each component.

Open it by double-clicking `index.html`. No server, no `npm install`, no network.

## How it is organised

A cover, two opening sections (*Por onde começar* — a door per audience; *O argumento* — the same
page with and without the system), then five chapters:

| Chapter | Sections |
| --- | --- |
| 01 Marca | selo (versions, live minimum-size rule, misuse), palette with measured text contrast, type lab, cubo impossível in every hue, voice, photography briefs |
| 02 Fundamentos | token explorer (role → brand alias in each theme), scales, motion and breakpoints, the three themes side by side, the live contrast table, icons |
| 03 Componentes | every component running, filterable; contract components show the exact HTML they produce |
| 04 Aplicações | the colour-band lab (refuses pairings below 4.5:1), the templates in device frames, the Sab.IA platform |
| 05 Uso | install routes, adoption levels, files written for agents, quality metrics |

The theme switch in the top bar re-themes the whole page; the contrast table and the quality
figures re-measure themselves when it changes.

## It cannot drift

Nothing on the page is transcribed by hand:

| What you see | Where it comes from |
| --- | --- |
| Every component demo | `dist/rse.js` — the same file the templates execute; demos in `demos.js` |
| Palette, CMYK, scales, rules | `brand.json`, via the generated `showcase-data.js` |
| Token explorer | `dist/tokens.json` and the manifest's per-theme declarations |
| Component list, props, counts | `rse.manifest.json` + `docs/components.md` |
| Contrast verdicts | `scripts/contrast-pairs.mjs`, measured from the live DOM with the WCAG formula |
| Quality figures | `scripts/audit-baseline.json` and `scripts/test-pages-baseline.json` — the CI ratchets |
| The artefacts | the real template files, running in `<iframe>` |

`showcase-data.js` is regenerated by `npm run sync` and verified by `npm run check` — a stale one
fails the build. CI opens the page in Chromium at 1280 and 360 px and runs axe-core on it.

## Files

```
index.html         the document and its section structure
showcase.css       page layout — every colour a token, no gradients
showcase.js        renders each section, measures the DOM, drives the theme switch
demos.js           one demo per component, plus its one-line pt-BR gloss
showcase-data.js   GENERATED by scripts/build-showcase.mjs — do not edit
```

React 18.3.1 UMD lives in `../assets/vendor/`, so the page never reaches for a CDN.

## Adding to it

- **A new component** appears in the gallery on its own once it is in the manifest. Give it a demo
  and a gloss in `demos.js` (see `docs/authoring-components.md`, step 4).
- **A new text-on-surface pairing** goes in `scripts/contrast-pairs.mjs`; the contrast table and the
  audit gate both read it.
- **A new section** is markup in `index.html` with an empty `id="mount-…"` element and a `mount()`
  call in `showcase.js`. Use tokens only; the page itself must pass the same gates as any page.

## Sharing it

- **By file** — send the repository folder, or the static kit from `npm run pack`. The page reaches
  `../assets/`, `../styles.css`, `../dist/rse.js` and the templates, so it needs its siblings.
- **By link** — serve the repository root on any static host; the page is at `/showcase/`.
