# Composition layer — design

Status: draft for review · Date: 2026-10-25

## Goal

An agent that receives only this repository's URL, and chooses its own stack (HTML, python-pptx,
SVG, Figma, a print pipeline), should be able to produce a deck, pitch, report, poster, social card
or one-pager that a designer would accept without a rewrite. The repo supplies the design
knowledge. It does not supply the toolchain.

## What was said, and what is assumed

Said by the owner:

- Cover decks, pitches and other non-web pieces, not only website components.
- Do not let the repo become bloated: a few specific paths, not a large library.
- The consumer may be an agent that sees only the GitHub URL and picks its own stack.
- The current `institutional-deck` is too simple to serve as a quality reference.
- Deliverable: HTML first, with PDF or PPTX export on demand.
- Aesthetic direction: **editorial, type-led** for all exemplars.
- The vocabulary should be broad, component-like, as long as that follows best practice.

Assumed (correct me):

- `brand.json` remains the machine contract and gains a `formats` section.
- The existing tokens, components and web templates are unchanged.
- Exemplars are built in HTML and rendered to PNG with the pre-installed Chromium. That is the
  author's tooling only; nothing in the spec depends on it.

## Non-goals

- A PPTX or JSON-to-render generator (possible phase 2; it can reuse the archetype data).
- A template per format.
- New components or tokens, unless an exemplar proves one is missing. If so it is flagged, not
  added silently.
- Changing brand rules in `AGENTS.md` (selo, motif, palette, language, accessibility).

## Architecture

Four layers, ordered from stable to specific. Breadth lives in layers 2 and 3.

| Layer | Content | Where |
| --- | --- | --- |
| 1. Foundations | grid, scale, colour pairings, motif use | existing tokens + `principles.md` |
| 2. Modules (~12, 2–3 variants each) | headline block, big number, quote, figure with caption, list, comparison, table, chart, timeline, callout, folio/footer, image-slot | `modules.md` + data |
| 3. Archetypes (~14) | compositions of modules, grouped by narrative job: open, argue, prove, compare, show, close | `archetypes.md` + data |
| 4. Formats (6) | 16:9 slide, 4:3 slide, A3/A4 portrait, 1:1 and 4:5 social, report cover | `formats.json`, merged into `brand.json` |

Everything is specified **without units tied to a stack**: sizes, margins and grid are fractions
of the canvas short side, so they convert to px, pt or mm.

## Files

```
DESIGN.md                          Root entry for URL-only agents. 10-line brief + routing table by intent.
docs/composition/
  principles.md                    The editorial grammar, with "what generic looks like" beside each rule.
  modules.md                       The module vocabulary and variants; includes chart and data rules.
  archetypes.md                    Layout specs: grid regions, hierarchy, colour pairings, "fails when".
  formats.json                     Canvas, margins, grid, type scale, safe areas, min text, max words.
  rubric.md                        ~12 yes/no self-critique checks, stack-agnostic.
  exemplars/
    specimen-sheet.png + .md       Every module and archetype on one sheet.
    institutional-deck/ pitch-deck/ poster-a3/ social-card/   PNG renders + the spec that produced each.
brand.json                         Gains `formats` and `composition` pointers (generated by build-brand).
```

`SKILL.md`, `AGENTS.md` and `README.md` link to `DESIGN.md`; none of them duplicates it.

### Entry point rules (`DESIGN.md`)

- Uses relative links only, so they work from github.com and from a clone.
- States the brief in about ten lines: who the brand is, the aesthetic in three sentences, the hard
  rules that never bend.
- Routes by intent (deck, pitch, report, poster, social, one-pager, web page) to at most four files
  per intent. Web work routes to the existing `AGENTS.md` flow.
- Asks for no `npm` step. Where a script exists, it is marked optional.

### Principles (editorial, type-led)

One idea per canvas · headline to body scale jump of at least 3:1 · left-aligned headlines on a
shared baseline grid with asymmetric margins · whitespace counts as content · the cube motif once,
large and cropped, never decorative · one band or accent hue per composition using the fixed
tint/ink pairings · flat fields only · Montserrat 800 headings, 700 uppercase eyebrows. The existing
`AGENTS.md` non-negotiables still apply and are linked, not restated.

### Rubric

About twelve yes/no checks the agent applies to its own render: the hierarchy reads in three
seconds · the scale jump holds · margins and whitespace match the format · contrast pairs pass ·
one motif · one band colour per section · density within the format limit · copy is pt-BR with no
emoji · no invented Sesc facts · placeholders flagged to the user · image-slots describe the shot
needed · nothing sits inside the safe-area margin. An optional `npm run lint:artwork` checks the
subset that can be read from HTML.

## Exemplars

Five images in total: the specimen sheet and four full pieces (institutional deck, pitch deck,
A3 poster, social card). Each is built to the principles with real tokens and official assets,
visibly placeholder copy, and `image-slot` boxes instead of photography. Each PNG sits next to a
short note that says why it works, so an agent that cannot see images still gets the lesson.

## Existing material

`templates/institutional-deck/` stays as a functional HTML starter. Its header comment and
`docs/recipes.md` point to the exemplars as the quality reference. No removals.

## Verification

- `npm run check` passes, including generated-file freshness for `brand.json`.
- `formats.json` is validated by `build-brand` (schema and the safe-area / min-size invariants).
- Each exemplar is checked against `rubric.md` by walking its checks and recording the result in
  its note.
- A fresh-agent test: a clean session given only the repo URL and the prompt "make a 10-slide
  pitch for X" produces a deck that passes the rubric. This is the real acceptance test.

## Rollout

1. `DESIGN.md`, `principles.md`, `formats.json`, `rubric.md`.
2. `modules.md` and `archetypes.md`.
3. Exemplars and the specimen sheet; adjust the modules if building them exposes gaps.
4. Link-up (`SKILL.md`, `AGENTS.md`, `README.md`, `recipes.md`, roadmap entry recording the
   decisions and the phase 2 option).
5. Fresh-agent test and fixes.

## Risks

- **Exemplars drift from the rules.** Mitigation: the rubric is applied to them and recorded.
- **The vocabulary grows without limit.** Mitigation: a new module or archetype must replace or
  absorb an existing one, or show that an exemplar cannot be built without it.
- **An agent ignores the images.** Mitigation: every exemplar has a written spec, and the numbers
  live in `formats.json`.
